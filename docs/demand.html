Study 01 / Independent analysis

Estimating the city’s hourly bike demand.

A chronological modeling study of urban rental demand, with observed weather, a seasonal baseline, and a winter holdout.

01 / The question

How much demand does an average hide?

Bike rentals follow a familiar commute pattern, but the level changes with the season and weather. This study asks whether a nonlinear model can estimate hourly rental counts more accurately than a recent weekday-and-hour average.

The task is conditional demand estimation: calendar information and observed weather are inputs. It is a foundation for planning research; it has not been validated as a day-ahead forecasting service.

02 / Study design

Let time set the boundaries.

The pipeline sorts all 17,379 hourly observations by date and hour. Training ends in June 2012; July–September is used for model selection; October–December is the final holdout. After selection, the model is refit on all pre-October observations.

The baseline is the mean demand for each weekday and hour in the latest 90 observed calendar days of training. Candidates include one-hot encoded ridge regression and histogram gradient boosting with 15, 31, or 63 leaves. Validation MAE selects the 63-leaf model.

The outcome cnt equals casual + registered. Both component counts are excluded, as are the record ID and raw date. Every preprocessing step is fitted on training data. Boosting uses a fixed iteration count, without a random internal early-stopping split.

03 / The evidence

Better estimates, through a changing season.

The selected model achieves an MAE of 42.26, compared with 89.90 for the recent seasonal baseline. RMSE is 67.36 and R² is 0.888. The gap widens in December as the baseline carries higher late-summer demand into winter.

A paired bootstrap over observed calendar days gives a 95% resampling interval of 47.9%–57.5% for the relative MAE reduction. Resampling whole days preserves within-day error structure, but not dependence between days.

04 / Interpretation

A useful estimate. A narrower claim.

The 53% reduction applies to this holdout and this baseline. It is not a measured reduction in fleet cost, shortages, or customer waiting time.

Weather is observed, not forecast. A planning system would need archived weather forecasts, rolling-origin evaluation across more seasons, and station-level availability. Missing hourly records are left missing rather than assumed to represent zero demand.

The next experiment would compare a weather-forecast version against week-ago and month-aware baselines, then evaluate asymmetric costs for over- and under-supply. Prediction intervals would need separate calibration; the bootstrap interval above concerns average error reduction.

05 / Open the work

Reproduce the analysis.

Python 3.12, pinned analysis libraries, and a fixed random seed of 42. The first run downloads the source archive from UCI. The pipeline writes the metrics, predictions, and charts used on this page.

python -m venv .venv
# Activate .venv, then:
python -m pip install -r requirements.txt
python run.py demand
python -m unittest discover -s tests
